# Арена — сервис киберспортивных турниров

Серверное приложение на Flask 3, Jinja2 и MySQL 8. Каталог, команды, турнирные заявки, сетки на выбывание и круговые турниры, кабинеты, приватная переписка и администрирование. Интерфейс работает на русском языке. Основные операции доступны с отключённым JavaScript.

## Запуск через Docker Compose

1. Установите Docker Engine с Compose v2 или Docker Desktop. Для чистой копии создайте файл настроек командой `cp .env.example .env`. В подготовленной локальной папке `.env` уже существует.
2. В `.env` заполните `SECRET_KEY` (минимум 32 символа), `MYSQL_ROOT_PASSWORD` и `DB_PASSWORD` тремя разными случайными значениями. Для генерации одного значения подойдёт `python3 -c 'import secrets; print(secrets.token_hex(32))'`.
3. Запустите команды из корня проекта.

```sh
docker compose up -d --build
docker compose ps
docker compose exec app flask --app app seed-demo
```

При первом старте MySQL импортирует `schema.sql`. Приложение ждёт готовности базы. `seed-demo` предназначена для пустого набора данных и запрашивает пароль демонстрационных аккаунтов. Откройте `http://127.0.0.1:8000/`. Для остановки используйте `docker compose down`. Данные MySQL и загруженные файлы хранятся в томах `arena-db` и `arena-uploads`.

## Как посмотреть демо

В демо десять турниров по восьми дисциплинам. Восемь турниров принимают заявки, в «Весенней лиге» уже доступен матч, «Осенний финал» находится в истории. Сначала откройте карточку завершённого турнира, затем войдите под одной из ролей.

| Логин | Что посмотреть |
|---|---|
| `arena_player`, `arena_rival` | Мои турниры, соперник, результат и переписка с организатором. |
| `arena_org` | Управление → карточка турнира → заявки, генерация сетки и результат матча. |
| `arena_admin` | Справочник игр и пользователи. |

Пароль общий для этих **демонстрационных** аккаунтов. В уже подготовленной локальной копии его значение находится в переменной `DEMO_PASSWORD` приватного `.env`. При новом развёртывании пароль выбирает оператор при `seed-demo`.

**Сквозная демонстрация.** Под `arena_org` создайте турнир по EA SPORTS FC на двух игроков, укажите даты и загрузите баннер JPG, PNG или WebP до 1 МБ. Опубликуйте его. Под обоими игроками подайте по заявке. Организатор одобряет обе заявки и генерирует сетку. Даты раундов распределяются по указанному интервалу турнира. Проверьте дату матча в личном кабинете игрока. Введите результат финала и откройте «Историю». Для командного турнира заявку подаёт капитан после набора состава в разделе «Команда».

## Запуск с собственным MySQL без Docker

Требуются Python 3.11+ и MySQL 8.4 (проверена 8.4.7). Для новой среды создайте виртуальное окружение и установите зависимости.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

Создайте пустую базу `arena` с `utf8mb4` и отдельного пользователя приложения. Импорт выполняет администратор базы, имеющий право создавать триггеры, например `mysql -u root -p arena < schema.sql`. Для обычной работы пользователю приложения достаточно `SELECT, INSERT, UPDATE, DELETE` на `arena.*`. Заполните `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` в `.env`. При подключении по Unix-сокету дополнительно задайте `DB_SOCKET`.

```sh
flask --app app seed-demo
flask --app app run --host 127.0.0.1 --port 8000
```

`APP_ENV=dev`, `test` и `prod` выбирают конфигурацию фабрики. Для production используется Gunicorn, выключен debug, обязателен `SECRET_KEY`. Под HTTPS установите `HTTPS_ONLY=1`. Для локального HTTP используется `0`.

## Обновление существующей базы

Для базы из предыдущей версии остановите приложение и сделайте резервную копию. Запустите из обновлённой копии `flask --app app upgrade-db` с доступом к прежней базе. Учётной записи для обновления нужны права `ALTER`, `INDEX`, `SELECT` и `UPDATE`. Для обычного запуска верните штатные учётные данные приложения.

В стандартной установке Compose при запущенном MySQL выполните:

```sh
docker compose stop app
docker compose build app
docker compose run --rm --no-deps app flask --app app upgrade-db
docker compose up -d
```

Команда добавляет дату завершения турнира и заполняет пропущенные даты матчей. Для завершённых записей старой версии используется прежний `updated_at`, для матчей — календарь раундов. Счёт, снимки результатов и уже заданные даты матчей сохраняются. Повторный запуск допустим. Новая база получает актуальную схему при первом старте.

## Повторный запуск уже подготовленной копии на этом Mac

Локальное демо работает на `http://127.0.0.1:8188/`. Отдельная MySQL 8.4 хранится в закрытом каталоге `instance/mysql8`. После перезапуска компьютера сначала запустите базу, затем приложение из корня этой папки.

```sh
instance/mysql8/runtime/bin/mysqld --no-defaults \
  --basedir="$PWD/instance/mysql8/runtime" --datadir="$PWD/instance/mysql8/data" \
  --mysqlx=OFF --skip-networking --socket="$PWD/instance/mysql8/local.sock" \
  --pid-file="$PWD/instance/mysql8/server.pid" --log-error="$PWD/instance/mysql8/server.log" --daemonize
APP_ENV=prod HTTPS_ONLY=0 .venv/bin/gunicorn --bind 127.0.0.1:8188 --workers 2 'app:create_app()'
```

## Проверки

```sh
.venv/bin/ruff check .
.venv/bin/pytest -q --cov=app --cov-report=term-missing --cov-fail-under=60
```

Интеграционные тесты создают базу `arena_test_<uuid>` и удаляют её после прогона. Используйте отдельный локальный тестовый экземпляр и учётную запись с правом создания и удаления **тестовых** баз. Доступ передаётся через `TEST_DB_HOST`, `TEST_DB_PORT`, `TEST_DB_USER`, `TEST_DB_PASSWORD` или `TEST_DB_SOCKET`. В подготовленной копии тестовый сокет уже задан в `.env`.

Для повторения замера импортируйте схему в отдельную пустую БД `arena_bench` и выдайте пользователю приложения доступ к ней. Далее выполните следующие команды в двух терминалах.

```sh
DB_NAME=arena_bench .venv/bin/flask --app app seed-benchmark
APP_ENV=prod DB_NAME=arena_bench .venv/bin/gunicorn --workers 2 --bind 127.0.0.1:8189 'app:create_app()'
```

```sh
.venv/bin/python scripts/benchmark.py --url http://127.0.0.1:8189/
```

## Сдача через GitHub

[GitHub Actions](.github/workflows/ci.yml) запускает Ruff и pytest с MySQL 8.4 для PR в `main` и при обновлении `main`. Задача `compose` проверяет сборку, запуск приложения с MySQL, HTTP-ответ главной и запуск контейнера от непривилегированного пользователя. После успешного push в `main` она публикует проверенный образ в GitHub Container Registry с тегом SHA коммита.

После первого прогона администратор репозитория может сделать `verify` и `compose` обязательными проверками для PR в `main` через Rulesets или Branch protection. Публикация образа и развёртывание в учебной сети выполняются отдельными шагами.

## Развёртывание в учебной сети

- На целевом узле настройте `.env`, задайте `APP_PORT=8000` и `HTTPS_ONLY=1`. После изменения настроек выполните `docker compose up -d --build`. Порт приложения привязан к loopback, а MySQL доступна внутри сети Compose.
- Для Caddy на том же хосте предусмотрен [пример конфигурации](deploy/Caddyfile). Имя `appket` должно разрешаться в адрес выбранного узла. После согласования развёртывания проверьте конфигурацию командой `caddy validate --adapter caddyfile --config deploy/Caddyfile`, установите её в используемый Caddy и добавьте корневой сертификат внутреннего CA в доверенные хранилища клиентов. Пример предполагает Caddy на хосте, а не в отдельном контейнере.
